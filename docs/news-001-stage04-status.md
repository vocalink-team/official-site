# NEWS-001 / 第04工程 実装記録

## 2026-10-23 実施済み
- 管理コンソールから `news-admin.html` に遷移する導線を追加。
- 管理者用リッチテキストエディターを追加（太字、斜体、下線、箇条書き、リンク）。
- HTMLの許可タグ方式のサニタイズを保存時・プレビュー時に適用。
- 記事の一覧、作成、編集、下書き、即時公開、日時指定公開、アーカイブを追加。
- SupabaseのNEWS専用5テーブルにRLSを設定し、非公開バケット `news-images` を作成。
- NEWS専用テーブルのデフォルト権限を最小化。匿名INSERT、一般TRUNCATEの不可を確認。

## 追加実装（2026-10-23）
- PostgreSQLトリガーで記事の新規登録・更新時に改訂履歴と監査ログを同一トランザクションで自動生成。
- 通常クライアントの監査ログ・改訂履歴への直接INSERT権限を取り消し。
- ROLLBACK付きDBテストで、改訂履歴1件・監査ログ1件の自動生成を確認。
- 管理画面に改訂履歴・監査ログの参照UI、非公開画像の添付と60秒署名付き管理者プレビューを追加。
- 画像の公開配信・端末実操作テストは未実施。

## 公開前の必須作業
1. 実際の管理者アカウントで編集・公開・下書き・アーカイブのE2Eテスト。
2. 公開ページ（一覧・詳細・検索・カテゴリ）を実装。現状は管理画面のみ。
3. 画像アップロードUIは実装済み。一般公開用の非公開画像配信処理は未実装。
4. 改訂履歴と監査ログの自動記録は実装済み。ブラウザでの実動作・不正操作試験が未完了。
5. ロール別RLS実動作試験、XSS試験、スマホ表示試験。
6. `VERSION.json` と全HTMLのバージョン表記を公開前に統一。
7. マイグレーションSQLをGitHubに正規化して記録（現在の `news-001-schema-draft.sql` は初期草案）。
8. 記事の `body_json` は `safe-html-v1`。公開画面でも必ず同等以上の安全なレンダリングを行う。

## 設計上の注意
- 予約投稿は `status='published'` かつ未来の `published_at` として保存し、RLSが公開日時まで閲覧を拒否する。
- 管理者判定は `app_metadata.role` を使用。プロフィールの自己申告ロールは使わない。
- 画像の公開URLを非公開バケットから直接配布しない。
- PRはドラフト。mainへのマージや本番公開は未実施。
