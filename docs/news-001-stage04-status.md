- 通常クライアントの監査ログ・改訂履歴への直接INSERT権限を取り消し。
- ROLLBACK付きDBテストで、改訂履歴1件・監査ログ1件の自動生成を確認。

## 設計上の注意
- 予約投稿は `status='published'` かつ未来の `published_at` として保存し、RLSが公開日時まで閲覧を拒否する。
- 管理者判定は `app_metadata.role` を使用。プロフィールの自己申告ロールは使わない。
- 画像の公開URLを非公開バケットから直接配布しない。
- PRはドラフト。mainへのマージや本番公開は未実施。

## 第05工程（2026-10-23）
- `news-public.js`: 公開専用の読み取りクライアント、本文の許可タグサニタイズ、記事カード。
- `news.html`: 一覧、タイトル・概要キーワード検索、カテゴリ絞り込み、重要記事優先、12件ずつのページング。
- `news-detail.html`: スラッグによる詳細表示、本文・公開日時・カテゴリ表示。
- `index.html`: 最新3件とNEWSリンクを追加。
- 一般向けページは `status='published'`, `published_at <= now()`, `deleted_at is null` を問い合わせ条件に設定し、DB RLSでも制限。
- DBのROLLBACK試験：匿名ユーザーから公開済み1件だけ閲覧可能。下書き1件・未来公開1件は閲覧不可。

## 第05工程 画像配信・第06工程 セキュリティ確認（2026-10-23）
- `supabase/functions/news-public-media/index.ts` を追加し、Supabase Edge Function `news-public-media` version 1 をデプロイ（公開エンドポイント）。
- エンドポイントは匿名アクセス可能だが、画像一覧・画像本体の双方で記事の公開状態、公開日時、未削除を毎回確認。
- Storageバケット `news-images` は非公開を維持し、サービスロールキーはサーバー環境のみで使用。
- 画像の最大サイズ・MIMEタイプ・記事IDとパスの整合性をDB制約で検査。一般公開時はメタデータを最小化し、`Cache-Control: no-store` を設定。
- `news-detail.html` に公開記事の添付画像を表示する処理を追加。
- RLSロールテスト（ROLLBACK付き）：匿名閲覧は公開済み記事のみ。下書き・未来公開は非表示。匿名の `news_media` 読み書き権限、`news_articles` 書き込み権限はいずれもなし。
- 既存のStorageポリシーを調査し、NEWSバケットに対する匿名読み取りポリシーがないことを確認。
